# 示範合作店選點

目前 270 家，對照官方快照 773 個設置位置，比例 34.9%。270 家名稱均為虛構，不代表已簽約、營業中或可實際收受；名稱相同也不表示與真實店家有關。

## 選點方式

- 保留原 24 個據點 ID 與座標，新增 246 個點。
- 在 12 行政區共 24 個商圈、市場或車站中心的 380 公尺候選半徑內，使用固定亂數 seed `20261024`。新增點與其他合作點至少相隔 85 公尺。
- 優先挑選距最近官方清潔箱至少 150 公尺、接近 250 公尺的候選點；另保留商圈需求假設點。新增點有 221 個距清潔箱至少 150 公尺。
- 距離依 Haversine 計算，為直線距離，非步行路線。最短 19 公尺、最遠 1,200 公尺；靠近現有清潔箱的點屬商圈情境，不代表現有容量不足。
- 商圈中心、候選座標、店名與垃圾量都是情境設定；沒有使用實測人流、地籍、店家登記或街道適宜性資料。未逐點驗證門牌、河川或公園邊界，不可當成真實服務名錄。

市場與商圈情境參考：[臺北市市場處攤販集中場](https://www.tcma.gov.taipei/Content_List.aspx?n=C34137546C201458)、[士林市場](https://www.tcma.gov.taipei/News_Content.aspx?n=1A4C7120ABFD0F9F&s=80903C918A9F93E3&sms=26C5BF03E7963F4E)。官方頁面只支持市場／商圈存在，並非此原型的人流或垃圾量證據。

## 維護及匯入

`npm run seed:stores` 重建固定候選點與名稱；`npm run seed:cloud` 產生日期相關交付及 SQL。相同輸入可重現選點。新增店預載三日不同件數與時間，多數使用未拍照補登情境，避免本機儲存被大量重複插圖耗盡。

現有 Supabase 專案依序執行 `supabase/demo-expand-parts/part-01.sql` 至 `part-06.sql`，每次只貼一份至 SQL Editor。原始整份 `demo-expand.sql` 超過 SQL Editor 限制，不要直接貼整份。每份均有交易及衝突忽略，可重跑。店名更新只限原本舊示範名稱且未認領的 21 家；保留自訂名稱、時段、已認領店家與既有交付。

本機模式補入缺少的示範點；雲端畫面只呈現 DB 實際回傳，不會用本機資料冒充已匯入成功。
