## 實際驗證的流程

- 民眾載入示範照片、模擬估算與送出；另一分頁的店家收受後，民眾端同步更新。
- 店家申報更新後，市府端立即顯示新申報量；查核備註重新載入後仍在。
- 拒收原因同步，拒收量不增加照片佐證量；停收與非開放時段影響地圖及交付。
- 實際 PNG 檔案經縮圖保存，店家端及重新載入後可見。變更垃圾類型須重新估算。
- 搜尋、示意地圖選點、只看收受中、店家切換、未拍照補登。
- 清運頻率與滿溢情境重算；過去無資料日期顯示未申報與未知，不視為零。
- JSON 匯出、取消重設、確認重設；三端在桌機與手機尺寸皆無頁面水平溢出。
- 未修改原版 HTML 的三端 HTTP 流程成功。
- 單檔 HTML 的交付、收受、市府比對及重新載入成功；除 HTML 文件本身外，沒有額外網路資源請求。

## 測試中處理的問題

- 先在尚未實作的 Vite 範本上取得三端流程測試失敗，再完成實作。
- 計算邏輯測試曾抓到「缺少有效照片不應變成零需求」與「完整照片進入查核鍵造成儲存膨脹」，已修正並通過回歸測試。
- 修正測試的重複文字定位及按鈕／選單選取方式，未放寬實際業務判斷。
- 最後一輪原以 4 個瀏覽器 worker 同時錄影，手機模擬部分在 context 收尾逾時。檢查失敗記錄後，改為本機 2 個、CI 1 個 worker，單案例上限 60 秒；完整重跑 14／14 通過。未以重試掩蓋這輪失敗，本機 retries 為 0。
