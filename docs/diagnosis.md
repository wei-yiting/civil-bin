## 實際補強

| 原版觀察到的限制                               | 新版處理                                                   |
| ---------------------------------------------- | ---------------------------------------------------------- |
| 只有單一大 HTML，維護與測試不易                | 拆為 React／TypeScript 角色元件、純計算、持久化及照片處理  |
| 未提供一致的專案啟動入口                       | README、lockfile、Node 版本、Vite HTTP 預覽與部署 workflow |
| 交付紀錄只記 `photo: true`，店家看不到實際照片 | 縮圖後保存 data URL，跨角色及重新載入後可看                |
| 收受時段是固定文字                             | 可調整時段、跨午夜及停收；提交前檢查是否開放               |
| 市府建議為固定敘述                             | 依需求、垃圾桶距離、容量、清運與滿溢情境重算               |
| 零照片而有申報量可能被視為正常                 | 明確提醒缺少照片佐證；未申報和零量分開                     |
| 市府缺少查核紀錄操作                           | 保存備註並綁定當時證據；新資料不沿用舊查核                 |
| 更改垃圾類型後仍可能送出前一估算               | 垃圾類型或參考物更動後，要求重新估算                       |
| 儲存失敗被忽略                                 | 明確回報且不顯示交付成功                                   |

新版標準網站從 HTTP／HTTPS 網址進入；`dist/index.html` 會載入分離的 JavaScript 模組，不能以直接雙擊取代伺服器。另提供內嵌所有程式、樣式、插圖的 `dist/standalone.html`，減少攜帶時漏掉資源檔的問題。單檔版仍需允許 JavaScript，檔案來源的本機儲存行為取決於瀏覽器。

本次對單檔版驗證其 HTTP 載入與主要流程、沒有額外網路資源需求；未宣稱已驗證每一款瀏覽器的雙擊開啟行為。
